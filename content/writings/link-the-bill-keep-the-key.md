# 钥匙不必交出去，还得看请求跑在谁那边

11 月 17 日，Anthropic 在 Claude Platform 上放出了 [linked billing](https://claude.com/resources/articles/linked-billing-on-claude-platform)，也就是链接账单，目前还是 beta。它要解决的事情很具体：你在第三方工具里用 Claude，不必再把 API 钥匙交出去；费用直接记到你自己的 Claude 账户上。

这件事我几乎每周都会碰到。要用一个写作、自动化，或者 coding agent 工具，常见的第一步就是：把 Anthropic 的 API key 贴进对方的设置页。钥匙一旦交出去，就相当于把能记账的密码给了别人。对方说会妥善保管，可对我来说，风险已经换了边。

我的判断也很简单。一个人用 AI 把生意跑起来，真正要看的不是又能在多少个工具里调用 Claude，而是两件事有没有分开：账单可以挂在我这边，钥匙却不必交出去。然后再问一层——这些请求，实际跑在谁的组织里。

## 链接的是账单，不是那串钥匙

以往的做法，Anthropic 说得很直：API key 像密码，谁拿到谁就能发请求，费用记在你头上，所以工具方必须负责保管。链接账单把这条路径改了。你在工具里点一次，跳到 Anthropic 自己托管的授权流程，用有 Owner、Admin 或 Billing 权限的账号，把整个组织关联过去。之后，请求仍由这个工具发出，但 Anthropic 直接向你收费。钥匙没有换手，工具方也就没有客户的 key 需要存储、加密或轮换。

关联之后，你可以给每个工具单独设每月限额，也可以随时取消，这些写在[给用户的说明](https://support.claude.com/en/articles/18467148-use-your-claude-platform-account-in-a-third-party-app)里。官方介绍还写明：平台能看到每个已关联客户的用量；至于某一笔请求由谁付钱，是平台在每次请求里决定的——可以记到你头上，也可以自己承担。若一笔标明由你付的请求没法记到你账上，接口会直接拒绝，而不是改记到平台头上。

眼下已经接上的工具里，和一个人做事比较近的，有 Linear、Railway、Warp、Gumloop、Kilo Code。Linear 的 Tom Moor 说，手动复制 API key 这件事，本身就不安全；有了链接账单，管理员可以一键把已有的 Claude 支出，用到 Linear 的云端 coding agent 上。名单还会变，以官方介绍为准。对我来说，值钱的不是又多了几个可以试用的入口，而是他们把「调用 Claude」和「交出钥匙」拆开了。

## 账单挂上了，请求却不一定按你的规则跑

真正让我停下来的，是官方文档里的那句限制。

[链接账单的开发说明](https://platform.claude.com/docs/en/manage-claude/oauth-apps/organization-billing-connections)写得很清楚：这些请求跑在平台自己的组织里。因此生效的是平台的速率限制、可用模型、服务层级、数据保留和加密密钥。你这边组织里的设置，带不过去——包括 IP 白名单、客户托管的加密密钥，以及零数据保留这类安排。需要 HIPAA、FERPA 或同等数据保护的用量，他们直接建议不要这样关联。

也就是说，你授权的是「让这个工具把费用记到我的 Claude 账户」，不是「让这些请求按我自己组织的规则来处理」。钥匙是留下了，数据怎么留、留多久、加密由谁管，仍然跟这个工具自己的 Claude 组织走。

限额也没有看起来那么硬。帮助文档写明，限额不是精确切断：越过上限的那一次请求仍会被执行，已经在跑的请求也会跑完，所以总额可能略高于你设的数字。用量按标价计算，和账单上的金额还可能有出入。另外，不是所有账户都能用这个功能。只有直接向 Anthropic 支付 API 费用的组织才行，走 AWS、Google Cloud 或 Azure 市场结算的不行，只有 Claude 订阅、没有 API 计费的也不行。Claude Max、Ultra、Team 订阅附带的月度 API 积分，以及一些合作和创业项目积分，也不能用来支付这类请求。

这些限制并不让这件事变得没意义。恰恰相反，它们提醒我：少交一把钥匙，解决的是保管和滥用的问题；它并不自动等于，请求已经回到了我的边界里面。

一个人同时跑内容、代码和生意，会用到很多工具。每多贴一把钥匙，就多一个可能被保存、被泄露、被拿去记账的入口。链接账单把这个入口收窄了，这是好事。可对话、文件和模型输出，仍然可能落在工具那一侧的组织里。把「不用交钥匙」理解成「数据还按我的规则走」，是自己骗自己。

## 我要留下的，是授权时能看清的边界

我不会因为这还是 beta，就继续把 API key 随手贴进每一个新工具。更不会把「已经关联了账单」当成万事大吉——关联只说明费用从哪来，没有说明请求在哪处理。

我更想留下的，是授权时的检查习惯。先问这次要关联的是账单，还是钥匙。能让 Anthropic 直接记账、钥匙留在自己组织里，就不要再把 key 复制给对方。每个工具都先设一个限额，不要默认不设上限。然后再看一眼官方写明的那条：请求跑在平台的组织里，我这边的数据保留和加密设置，并不会跟着过去。若这件事涉及客户或生意里更敏感的材料，这条要比「方不方便调用」更早被问到。取消关联通常在大约十秒内让新请求停下来，但已经在跑的请求仍会完成，并记在我头上。

不是拒绝使用这些工具。是点下「关联并授权」之前，先看清楚自己到底交出了什么，又留下了什么。
