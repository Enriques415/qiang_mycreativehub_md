这两天连续撞上两件事。一件是 GREP.AI 把 [AgentRun](https://agentrun.ai/blog/introducing-agentrun-run-smarter-agents-use-fewer-tokens) 开源出来，并在 11 月 13 日前后上了 [Hacker News](https://news.ycombinator.com/item?id=50471650)；另一件是 Google Antigravity 上线了 [Dynamic Workflows](https://antigravity.google/docs/dynamic-workflows/)，用 `/run-workflow` 让模型先写出一段脚本，再去调度一群 Agent。

产品完全不同。可我读下来，被钉住的是同一句不舒服的话：Agent 很会想事情，也很容易把同一件事情，明天再想一遍。

我的判断很简单。一个人用 AI 把生意跑起来，真正值钱的不是它今天发挥得更漂亮，而是那些会反复出现的活，想过一次之后，能被写成我还能看懂的流程。

## 它会想，并不等于该每次都从头想

AgentRun 创始人 Miguel Rios Berrios 在 11 月 10 日的[介绍文章](https://agentrun.ai/blog/introducing-agentrun-run-smarter-agents-use-fewer-tokens)里，开头就写得很直白：Agent 擅长把事情想清楚，问题是同一件事它会想了一遍又一遍。一份已经做过上百次的工作交给它，它仍可能重新发现同一套接口，重新读同一份文档，再重新搭一遍计划，而你为这些 token 再付一次钱。

这个观察并不新鲜，但它把对象说准了。他们盯住的不是「再做一个更聪明的聊天框」，而是那些会重复发生的知识工作：按规格核对一份文件、做尽职调查、给供应商做准入。换一批输入，步骤却差不多。普通的 Agent 套件擅长循环到把问题解开，却不擅长在同一类问题上变得更省事。Miguel 打了一个很容易记住的比方：这就像把一叠表格交给爱因斯坦，他会做完，可每张表他都会重新认真想一遍。

他们的做法是把「学会」从聊天记录里拿出来。打开学习之后，Agent 做完一轮会回头看，留下笔记：这次什么有用、什么没用、下次怎样更好。时间长了，它开始把这类问题写成一套工作流，后面的运行直接复用，不必再从头计划。Miguel 在 Show HN 的说明里还补了一句更具体的话：他们发现，重复任务跑过大约一百次之后，多数时候它已经可以直接把工作流跑完，而不再靠大模型一圈圈摸到答案。工作流便宜，账单也就下来了。

这些数字是他们自己的观察，不是我复现过的结论。我记下的是方向。更让我停住的，是他那句几乎被随手写下的话：**这类问题里，大多数根本不需要一个 Agent。**

这句话有点刺耳，却很诚实。我们很容易默认：既然模型会办事，就把重复的活也交给它「再当一回聪明人」。可如果步骤已经清楚，判断点也可以被单独拿出来，让它每天重新探索一遍，并不是认真，只是浪费。

## 计划一旦写成脚本，我才知道自己在放行什么

另一边，Antigravity 的 [Dynamic Workflows](https://antigravity.google/docs/dynamic-workflows/) 走的是更硬的一条路。你输入 `/run-workflow` 加上任务，主 Agent 会先读内置技能，写出一段简短的 Python 脚本：哪些步骤并行，哪些必须按顺序，每个子 Agent 要带回什么样的结果。除非你事先放行，否则它会先把脚本摊开，等你点头，再放到后台跑。

这段脚本还可以存进项目，下次直接再跑。官方文档举的例子都很日常：给这个分支里改过的每个文件做一次审查，给每个包做一次审计，先写失败测试再修代码。子 Agent 各自待在自己的对话里，文件读取和测试日志也不再灌进主对话。计划不再只活在聊天记录里，它变成一份你可以打开的东西。

我在意的不是 Python 本身，而是「先写下来，再放行」。聊天里的计划会漂移，你很难指着某一句说：我就批准了这个。脚本不一样。Antigravity 也写得很清楚：一次批准只覆盖眼前这一份脚本，改过之后必须再审一次。这很笨，但也正是我要的笨。

对一个人和一套自己的系统来说，这比「让它自己组一队去谈」更让人放心。即兴的多 Agent 协作偶尔很惊人，可我无法把它当成明天还能用的方法。能存下来、能对照、能拒绝的计划，才配进入日常。

## 我会让它想第一次，不会让它把第一次再演一遍

我自己这套写作和发布流程，其实就是典型的重复工作。选题、成稿、封面、飞书、站点，每天的输入不同，路径却几乎不变。最偷懒的办法，是每天重新跟它聊一遍「我们今天怎么做」。最省事的幻觉，则是指望它自己越来越会，于是连步骤也一并交给临场发挥。

我现在更想要的是中间那一档。第一次遇到新情况，让它去想、去试、把坑留下。等这条路通了，就把它写成流程：哪些步骤可以自动走，哪些判断必须先问我，哪些输出必须留下可复查的文本。之后再跑，不是为了看它能不能再次想明白，而是看这份流程今天还成不成立。

这也是我给自己设的界限。流程必须能被打开看，最好像站点上的 Markdown 一样，改过能对照。Agent 可以提议更新步骤，但不能悄悄改掉我已经放行的那一份。它在例外上仍然有用——供应出了岔子、稿件需要对一次特殊的事实、某个接口今天突然变了——可例外应当回到流程里，而不是把整件事重新变成一场即兴演出。

所以，我不会急着换一个「会自我进化」的新工具，来证明自己够新。AgentRun 和 Antigravity 只是把同一件事说清楚了：重复的活，不该永远停留在 Agent 循环里。想过一次就够了。剩下的，请写成我还愿意再读一遍的流程。
