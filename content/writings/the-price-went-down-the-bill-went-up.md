11 月 16 日，我把 Anthropic 的定价页从头看到尾。一排箭头全部朝下：Fable 从每百万 10 美元、50 美元落到 8 和 40；Opus 从 5 和 25 落到 4 和 20；Haiku 从 1 和 5 落到 0.1 和 0.5。最后那一行看着像打错了小数点。

同一页往下几行，有一句脚注：Claude 4.7 之后的模型换了新的分词器，同样的文字会产生大约多三成的 token。

两句话都是真的。乘起来就不是降价了。

## 先把这道乘法做完

我拿三行降价各算了一遍，用的是同一套粗暴办法：单价的变化，乘上单位的变化。

Opus，从 4.6 的 5 和 25 降到 5.5 的 4 和 20，单价打了八折；同样的文档多出三成 token，乘 1.3。0.8 乘 1.3 等于 1.04。同一份活，贵了四个点。

Sonnet，从 4.6 的 3 和 15 到 5.5 的 2 和 10，单价是三分之二；再乘 1.3，0.87。便宜了大约一成三，不是表上看着的三成三。

Haiku，从 1 和 5 到 0.1 和 0.5，乘 1.3 之后是 0.13。这一行是真降，降得也确实狠。

三行箭头一样朝下，真实幅度分别是便宜 87%、便宜 13%、贵 4%。表上降幅看起来最小的那行，其实是涨价；降幅看起来最夸张的那行，是真的。

有个前提得说清：这 4% 只咬那些从 4.6 及更早的模型迁移过来的人。如果你的项目已经在 4.7 的线上，Token 早就按新尺子量了，从 Opus 5 换到 5.5 就是干干净净的两成降幅，没有暗门。

所以这不是谁在骗人。是同一张表上，三行的含义本来就不一样，而表上只印了一个维度。

## 分词器不是小数点，是尺子

token 不是字数。它是各家自己训练出来的切词方式，同一段文字，不同厂商切出来的块数不一样。

有人把这件事量过了。TensorZero 拿 OpenAI 的分词器当 1.00 的基准：Claude Opus 4.7 在纯英文上是 1.57 倍，YAML 1.53 倍，JSON 1.70 倍，工具定义 2.65 倍。Gemini 3.1 Pro 在同一组内容上是 1.06、1.18、1.11、1.82。Playcode 拿一份 TypeScript 文件做过更极端的对照：同一份代码，GPT 那边 681 个 token，Claude 这边 1178 个，1.73 倍。

这里有个细节，我自己读到时停了一下。开发者 Abhishek Ray 用 Anthropic 自己的 count_tokens 接口跑了七份真实内容，技术文档 1.47 倍，一份真的 CLAUDE.md 1.445 倍，shell 脚本 1.39 倍，TypeScript 1.36 倍。而中文和日文的散文，是 1.01 倍。

也就是说，这次所谓的三成涨价，对写中文的人几乎不存在，对天天喂代码、JSON 和工具定义的人最狠。同一次改动，在不同人身上是不同的事。

我两样都干。写稿是中文，做产品是代码。所以我这个月的两份账单，走向是相反的。这件事没法从一张公开的费率表上读出来，只能自己拆开看。

## 乘数不止一把

分词器只是第一把。真实账单上还叠着几层，每一层都不在任何定价页上。

思考 token 算输出。模型在回答之前先想的那一段，看不到，但照价计费。一个看起来用了两千输出 token 的任务，底下可能花了一万五。

系统提示和工具定义每次都要重发。一个两千五百 token 的系统提示，加二十个各一百五十 token 的工具，模型还没听你说第一句话，每次调用已经先吃掉五千五百个输入 token。缓存能挡住大部分，但只挡命中的那些。

失败和重试也计费。解析失败、校验没过、被你打断，那一轮的 token 已经产生了。一个从第一步重跑的任务，前面所有步骤都要重新付一遍钱。

分档也会咬人。Haiku 5.5 的 0.1 和 0.5 只对十万 token 以内的提示有效，过线就是 0.5 和 2.5，同一个模型、同一页纸，五倍。而提示长度算的是全部输入，包括缓存读和缓存写，按单次请求各自定价。一个平时都在线下的活，偶尔冒一次头，不会像你想的那样摊平。

把这些叠起来看，比较「每百万 token 多少钱」这件事本身就失效了。行业里近来在推另一个口径：跑完一件活多少钱，cost per completed task。它把分词效率、单价、一次任务要走多少步、成功率全算进去。数字难看，但它和你的银行账户是同一个单位。

## 交易里最早学会的一课

我做交易的头一年，看的是费率表。手续费万分之几，比一比，选个便宜的。

第三年才明白，真正吃掉收益的不是那一栏。是报价和成交价之间的那一截，是挂单没成交、改价追进去多付的那几跳，是持仓过夜的资金费，是一笔单子被拆成几笔之后多出来的滑点。费率是给外面看的，成交价才是成本。

这两件事在我眼里是同一件事。牌价是一个广告位，乘数才是成本结构。区别只在于，交易的乘数你每天在盘面上看得见，API 的乘数藏在分词器、重试和档位里，不到月底不出现。

所以我一直觉得，一个自己付账单的独立开发者，最先该长出来的能力不是选型，是记账。

## 一个把单位换掉的小工具

这几天有个日本的独立开发者做了个很小的东西，我很喜欢。一个纯静态页面，把六家模型的「每百万 token 多少美元」换算成「一次调用多少日元、一个月多少日元」。预设里有两个很具体的场景：识别一张照片、来回一轮对话。你还能调 token 数、月调用量、汇率。

按同一组用量算——输入 1600、输出 400、每月一千次——六个模型的月成本从 48 日元到 1080 日元。二十二倍。

这个工具没有让价格更准确，它让价格变得可比。美元每百万 token 是一个没法在脑子里做判断的单位；一个月一百八十日元和四千日元，谁都知道该怎么选。

我一直觉得「不焦虑」不是不看账单，是把账单变成一个能算的东西。看不见的成本才会让人半夜醒过来，算得出来的数字反而让人睡得着。

## 我会怎么做

我不会因为这次降价就去换模型，也不会因为那三成就不换。这两个反应都太快了，快到我其实什么都没量。

我要做的是把自己那个系数拿出来：用自己的稿子、自己的代码、自己那套工具定义，跑一遍 count_tokens，得到属于我的乘数。TensorZero 那两个数字 1.57 和 2.65 之间差着整整一个身位，落在哪一头，取决于我每天到底在发什么。

牌价是别人给的。乘数只能自己量。

定价页没有骗人。是我一直看错了那一栏。
