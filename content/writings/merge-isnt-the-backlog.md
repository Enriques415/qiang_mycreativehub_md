11 月 18 日，Google Labs 的 Justin Toupin 介绍了 [Stitch Loop](https://blog.google/innovation-and-ai/models-and-research/google-labs/stitch-loop/)。这是 Stitch 的新方向，目前还是实验：一个会长期跑下去的产品 Agent，连上你的代码仓库和线上指标，再按你定的目标，一直找还能改哪里。

这件事并不陌生。写功能和修页面，现在已有不少 coding agent 能帮忙。可官方也说得很直：它们的工作，往往在 pull request 合并的那一刻就结束了。代码一上线，真正费神的是另一截——漏洞、变慢的结算、埋在反馈里的注册流失。一个人同时跑内容和生意，这一截常常是夜里才有空看的。

所以 Stitch Loop 的卖点很清楚：上线不是终点，循环可以全天接着跑，直到目标达到，之后还继续盯着，以免指标又滑下去。我的判断却更窄一点。一个人用 AI 把生意跑起来，真正要看的不是又多了一个能通宵改产品的循环，而是目标交给它之后，下一件事先由谁来排。合并权留在自己手里，必要，但还不够。

## 它接上的是代码，也是你的目标

按照官方介绍，你先把 GitHub 和产品上下文接进去：日志、用户行为、反馈，也可以用他们说的 180 多种集成、自己的 MCP 服务，或者本地 CLI 上传。随后，Stitch Loop 会按你关心的、可衡量的结果，跑一组会持续下去的循环。默认带三个：安全、延迟、无障碍。你也可以自己加，比如提高结算转化。

每个循环的路径差不多。它先根据产品里的证据，提出值得推进的机会；每个机会会带上一种或几种方案，以及取舍和范围，必要时还有视觉设计选项。你选了方向之后，它在隔离的云沙箱里写代码，开出 GitHub 的 pull request 等你审批，相关的话还会附上截图和视频。合并之后，它继续看线上数据，从结果里调整下一轮判断。目标达到了，它也不会停，只是改成守着，怕指标再掉。

官方把控制权写得很干脆：最终决定权在你，不审这条 PR，改动就不会合并。安全循环还配了 Gemini 4 Carbon 的安全能力，以及 DeepMind 的 CodeMender，用来扫漏洞，再带着证据开出修复用的 PR。这些我都相信是有用的。一个人的小产品，最容易漏掉的，往往就是这类不会自己出现在待办里的事。

它也可以给别的 coding agent 当一层服务，比如官方点名的 Google Antigravity。其他 Agent 能通过 Stitch 的 CLI 和 MCP，把产品上下文拿走。Slack 里用 @stitch，还能拿每日摘要、建新的循环。候补名单已经放开，地址在 [stitch.google.com/loop/waitlist](https://stitch.google.com/loop/waitlist)，Google AI Ultra 的用户会优先。

## 审批的是补丁，排期的可能已经换人

真正让我停下来的，不是它会不会在沙箱里写代码，而是建议从哪来。

循环一旦接上指标，下一件「值得做的事」，就会从你的待办，慢慢变成它根据证据排出来的机会列表。你仍然可以不选、不合并，可队列本身已经在被重写。官方也写了，目标达到之后，它会继续盯着指标。这意味着：你即使暂时没有新想法，循环也还在为那个数字寻找下一处改动。

这对一个人做事，既省力，也危险。省力的是，安全和无障碍这类本来容易被往后放的事，终于有了一个会持续提醒你的来源。危险的是，如果你把「提高结算转化」设成一个长期循环，它会很勤奋地围着这个数字找方案。方案也许成立，也许只是在透支信任、把页面变得更吵，或者把你本来不想碰的流程改掉。你一封一封审 PR，会觉得控制权还在，可议程已经换了手。

指标是证据，不是产品方向本身。用户行为能告诉你哪里掉了，却不能替你决定：这个问题值不值得在这个时候改，改完是不是还像你想做的那个产品。一个人同时跑内容、代码和生意，时间本来就碎。最省事的用法，就是让循环把待办填满，然后自己只负责点合并。那才是我更要小心的地方。

## 我愿意给它窄任务，不愿意把排期交出去

我还没排到试用的位置，所以下面只是我自己会守的界限，不是使用报告。

如果后面能用上，我更愿意先开一个范围已经清楚的循环，比如已知的安全问题，或者某一条已经慢到能感觉出来的链路。这类任务里，「下一件该做什么」本来就不那么开放，循环更像是把证据和补丁送到我面前。我不会一上来就给它一个会永远跑下去的目标，比如「把产品变得更好」，或者只盯着某一个增长数字，让它自己决定节奏。

它给的建议，我会当成简报来读，而不是一张必须清完的工单。方案的取舍写得再清楚，也只是它在既定目标下的推理。目标本身对不对，还是得我来判断。哪个循环允许继续跑，哪个该停，这也是排期的一部分，不能因为合并权还在，就默认这些循环都可以一直开着。

发布权仍然留在我这边。PR 要看，站点上的稿也还是我自己核对过才上线。循环可以通宵找问题，但下一件事先做什么，还是得回到我自己的判断里。

对我来说，Stitch Loop 真正有价值的地方，不是它承诺让产品自己持续变好，而是它把上线之后那截容易被忽略的工作，变成了看得见的建议和补丁。至于这些建议会不会进入我的待办，仍然该由我来排。
